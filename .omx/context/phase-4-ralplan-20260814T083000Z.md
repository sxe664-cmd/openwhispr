# Slice 4 Ralplan: Encounter Transcription and Clinical Notes

## Approved architecture

Extend the existing path rather than introducing a second recorder:

`Encounter start -> queueMeetingNoteNavigation -> PersonalNotesView -> meetingRecordingStore.startRecording`

The encounter remains linked to exactly one local note. The note remains the canonical transcript store. Clinical outputs are stored separately in a local `encounter_outputs` record so they do not overwrite user-authored note content or generic `enhanced_content`.

## Work packages

### WP1 — Persistence and IPC (Terra High)

- Add a migratable `encounter_outputs` table keyed uniquely by `encounter_id` and carrying transcript hash, summary, SOAP, status (`pending`, `processing`, `ready`, `failed`, `stale`), provider/model metadata, safe error code, and timestamps.
- Add database methods for get/create/update output, mark stale by transcript hash, and idempotent retry updates.
- Add encounter/output IPC and preload/type declarations.
- Harden encounter start/recording ownership so an active recording cannot silently attach to another encounter; same-encounter retry reuses the active session.
- Persist the final transcript before completing the encounter; diarization transcript updates invalidate output by hash.

### WP2 — Local/BYOK generation (Terra Medium)

- Add a small clinical output orchestrator using the existing reasoning IPC/provider path.
- Default to the configured local reasoning route; allow BYOK only when explicitly configured and never silently fall back to a remote provider.
- Generate Summary and SOAP separately from the canonical transcript, with bounded prompts and structured parsing/fallback.
- Persist processing/ready/failed states and fixed safe public errors; preserve transcript on every failure.
- Add unit tests for local success, missing local model, explicit BYOK, no-fallback, retry, and transcript-hash staleness.

### WP3 — Encounter note UI (Luna High)

- Add Summary and SOAP tabs/sections beside the existing transcript in the meeting note editor.
- Display Recording, Processing transcript, Separating speakers, Generating notes, Ready, Stale, Failed, and Retry states.
- Trigger generation after final transcript/diarization settlement without duplicate requests; allow explicit retry.
- Keep quick dictation and ordinary notes unchanged.
- Add focused component tests for state transitions, stale output, retry, and safe errors; add translations in all locales.

## Acceptance/test specification

- Starting the same encounter twice reuses one note/session; starting a different encounter while recording is safely blocked.
- Stop persists transcript before completion; diarization updates speaker labels and marks prior clinical output stale.
- Local model generates and persists both Summary and SOAP offline.
- Missing local model fails safely without making an external request.
- Explicit BYOK works only when configured; no provider configuration does not fall back to cloud.
- Restart preserves encounter, transcript, speaker labels, outputs, and retry states.
- Existing dictation, meeting recording, diarization, notes, lint, typecheck, i18n, tests, and renderer build remain green.

## Review risks

- Prevent output generation from racing against diarization persistence.
- Do not expose raw model/provider/IPC errors in the renderer.
- Do not change generic note enhancement behavior or quick dictation routing.
- Do not add direct Google Calendar/OAuth or cloud OpenWhispr calls.
