# Phase 3 Ralplan: Encounter Integration

## Approved architecture

Introduce a real local `encounters` table. Calendar projection owns scheduled encounter rows; existing meeting notes remain the transcript/document storage. The stable Phase 1-2 AIReceptionist occurrence ID is the unique external identity. A nullable `note_id` links an encounter to the one local meeting note created when recording begins.

## Work packages

### WP1 — Terra High: encounter persistence and idempotent start

Touch `src/helpers/database.js`, `src/helpers/receptionistCalendarBridge.js`, `src/helpers/meetingDetectionEngine.js`, `src/helpers/ipcHandlers.js`, `preload.js`, `src/types/electron.ts`, and focused tests. Add schema/migration, safe upsert/tombstone behavior, local encounter IPC, and one start path that reuses an existing note on retries, calendar joins, hotkeys, and repeated clicks. Preserve note-linked data and never overwrite local lifecycle/context fields during calendar refresh.

### WP2 — Luna High: Home encounter-first UI

Add focused encounter card/list components and adapt Home/History/Upcoming surfaces. Show upcoming, in-progress, and completed encounters with cached/offline status and safe actions. Reuse the existing PersonalNotesView and recording/transcription/diarization flow; do not duplicate audio logic. Keep quick dictation available as secondary history.

### WP3 — Terra Medium: Calendar & Reminders and AI Receptionist surfaces

Add dedicated sidebar/page surfaces and matching Settings sections. Reuse managed sidecar status and safe IPC. Show ready, syncing, stale, unavailable, and error states without setup/OAuth prompts or secrets. Keep Microsoft/Apple integrations separate and keep Google explicitly managed by AIReceptionist.

## Acceptance/test specification

- Repeated feed snapshots produce one encounter per stable calendar occurrence.
- Safe event metadata updates preserve note links, lifecycle, and context.
- Tombstones cancel unstarted encounters; note-linked encounters remain intact.
- Sidecar/network failure leaves cached encounters usable.
- Starting from Home, calendar join, or meeting hotkey reuses one encounter/note.
- In-person and telehealth choices reach existing recording/diarization routing.
- Calendar & Reminders and AI Receptionist have dedicated navigation/settings surfaces.
- No direct Google OAuth or second Electron host returns.
- Run focused tests plus `npm test`, `npm run lint`, `npm run typecheck`, `npm run i18n:check`, and `npm run build:renderer`.

## Explicit non-goals

SOAP/summary generation, new transcription models, cloud APIs, and signing/notarization remain Phase 4/release work.
