## Review-driven objective

Fix the two Terra blockers from review cycle 1 before the next code review:

1. Guarantee that delayed Summary/SOAP generation cannot publish output for an older transcript or diarization revision.
2. Ensure final encounter transcript completion refreshes the active renderer note through the existing note-update path, including short recordings and skipped/failed diarization.

## Approved contract

The main process/database owns one canonical transcript token:

`{ transcriptRevision: integer, transcriptHash: sha256(canonical note.transcript) }`

The note remains the source of truth. The renderer must not create a competing transcript hash or publish ready output without a main-process token check.

### State transitions

- Any canonical transcript change (ordinary edit, final recording completion, or diarization) increments the monotonic transcript revision, recalculates SHA-256, and marks linked outputs `pending` when empty or `stale` when content exists.
- A guarded generation begin atomically captures the token/transcript snapshot and marks the selected output types `processing`.
- A guarded finish persists Summary/SOAP as `ready` or `failed` only when the expected token still matches; otherwise it returns `applied: false` and leaves the newer revision pending/stale.
- The monotonic revision prevents ABA cases where text changes A → B → A.
